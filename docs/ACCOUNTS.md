# 账户、邮箱验证与禁用管理

## 本机测试邮件

当前按用户选择使用 `MAIL_TRANSPORT=file`，验证码与密码重置链接保存到私有 `data/mail/`，不会向外部邮箱投递。

1. 网站“登录 / 注册 → 注册账户”填写邮箱，点击“获取验证码”。
2. 在项目目录执行 `npm run mail:preview`，查看最新本地测试邮件，取出 6 位验证码。
3. 回网站完成注册。验证码绑定邮箱，10 分钟内有效，最多尝试 5 次，成功后失效。
4. 测试找回密码时，在登录窗口点“忘记密码”，申请后再次执行 `npm run mail:preview`，打开邮件内的本地重置链接。

测试邮件包含一次性凭据，请勿截图公开、提交 Git 或作为公共静态文件提供。网站与 API 不会直接返回验证码、重置令牌或本地邮件列表；开发服务器也禁止通过静态路径读取 `data/`、SQLite 或环境文件。生产环境禁止本地邮件文件模式。

## 切换 SMTP

在私密 `.env` 或服务器环境变量中配置，修改后重启后端：

```dotenv
MAIL_TRANSPORT=smtp
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_SECURE=false
SMTP_USER=no-reply@example.com
SMTP_PASS=邮箱SMTP授权码
SMTP_FROM=no-reply@example.com
PUBLIC_ORIGIN=https://image.yidianhub.com
```

465 端口通常对应 `SMTP_SECURE=true`；587 通常为 `false`，客户端会要求 STARTTLS，不降级明文或关闭证书验证。具体参数以邮箱服务商提供的信息为准。`SMTP_PASS` 通常是专用授权码，不一定是网页登录密码。可按服务商要求配置发信域名、SPF/DKIM 等，实际投递和进入收件箱的情况仍须联调。

`MAIL_TRANSPORT=disabled` 完全关闭邮件能力。未配置可用邮件服务且后台要求验证时，网站暂停新注册，找回密码不可用；已有账户仍可正常登录。后台显示“已配置 SMTP”表示参数齐全，不代表已验证真实投递。本轮没有发送真实外部邮件。

## 注册与积分设置

管理员进入“运营管理 → 注册与邮箱”：

- 开放/关闭新用户注册。
- 启用/关闭邮箱验证要求。
- 设置新用户赠送积分，填 0 关闭赠送。

`ALLOW_REGISTRATION`、`SIGNUP_CREDITS`、`EMAIL_VERIFICATION_REQUIRED` 仅在数据库首次初始化账户设置时使用，以后在后台修改。生产默认不开放注册、赠送积分为 0；生产和本地开发默认要求邮箱验证，测试环境为保持隔离用例默认不要求。

尚无管理员时，受信任服务器终端可使用 `node dist/scripts/admin.js registration true` 临时开放注册；完成邮箱验证、注册并 `promote` 后再以同样命令设为 `false`。本地源码对应 `npm run admin -- registration true`。该命令不会绕过验证要求。

积分在成功注册时按当时设置一次性发放；需要验证时，完成验证码校验后才创建账户与积分流水。设置修改不补发、追扣或修改现有积分。后台设置有版本检查，避免多个管理窗口覆盖修改。

启用验证后，历史未验证账户可登录查看作品与流水，但上传素材、提交生成、兑换积分或创建支付订单前必须验证邮箱。界面会显示验证入口。仅本次迁移前已有、通过本地方式设置的管理员保留邮箱确认状态以避免锁死管理员；这不是完成真实邮件投递的证据，其他历史账户不会自动标记已验证。

## 找回密码与会话

登录窗口“忘记密码”申请一次性重置链接，30 分钟内有效。存在和不存在的邮箱收到相同网站响应，网站不会通过这个入口公开查询某邮箱是否注册。禁用账户不发送重置邮件。

令牌放在链接 fragment（`#reset=...`）中，前端读取后移除地址栏中的令牌，不写进服务端访问 URL。数据库只保存令牌摘要；重置时检查有效期、使用状态与账户鉴权版本。成功重置会撤销该账户全部登录会话及旧重置凭据，用户需用新密码重新登录。

验证码和重置邮件受每 IP 的接口限流、每邮箱每种用途 60 秒冷却及每小时最多 5 次申请限制。验证码错误累计 5 次失效；重新申请会使之前同用途的凭据失效。邮件发送失败不会把验证码输出给调用者。以上是基础防护，不能替代公开大规模运营时的验证码、风控和监测。

## 禁用与恢复用户

“运营管理 → 用户管理”支持账户状态筛选。在用户详情中选择“禁用账户”或“恢复账户”，填写原因后确认。

禁用时：

- 全部已登录会话立即撤销，禁止再次登录和发起新的模型调用。
- 尚未提交上游的 queued 任务取消，冻结积分在同一个事务中一次性退回。
- 已经发到上游的 running 任务继续等待并按结果结算，无法保证撤销正在执行的上游生成或退回上游费用。
- 不删除账户资料、已有作品或消费记录。支付商真实已付订单的有效回调仍按资金账务入账，不能丢弃已付款项。

恢复时不恢复旧会话，用户需要重新登录；禁用前申请的旧密码重置链接不能在恢复后重新使用。管理员不能禁用自己，系统保留至少一位可用管理员。每次状态变更保留操作者、时间与原因。

## 当前边界

本轮完成邮件验证码注册、历史账户验证、找回密码、用户禁用/恢复及注册赠送控制。真实 SMTP 投递、公开网络压力测试及手机目视操作仍需后续验收。作品删除、存储限额和真实支付退款不在本轮实现范围内。
