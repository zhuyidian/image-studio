# Yidian-Image

面向普通用户的独立图片创作服务。账户、积分、订单、任务与作品由本站管理；现有 New API 负责模型接入。计划域名：**https://image.yidianhub.com/**。

这是可在本地运行的首版 MVP。默认使用**模拟图片提供者**，不会调用 New API、不会产生模型费用、不会实际收款。模拟图带有 `LOCAL DEMO · NOT AI GENERATED` 标识，不用于证明真实模型的生成或编辑效果。

本机当前已切换到 New API，首批 GPT Image 2 试用仅开放标准单张方图。最新核对、异常任务退款、人民币成本口径与验收范围见 [首轮试用检查](docs/PILOT_REVIEW_2026-11-12.md)。README 的默认模拟模式描述指新安装配置，不表示当前本机模式。

## 本地启动

需要 **Node.js 24+**。数据库使用 Node 内置 SQLite，无需先安装 Docker 或数据库服务。

```powershell
cd C:\dunn\project\image-studio
npm install
npm run dev
```

打开 **http://127.0.0.1:5173/**。可以注册本地账户，或点击“登录 / 注册 → 进入本地演示”。演示账户是共享测试账户，请勿上传私人图片。演示入口在生产模式或真实模型模式下不可用。

- 前端：127.0.0.1:5173
- API 与任务 Worker：127.0.0.1:8787
- 数据库：`data/studio.sqlite`
- 图片：`data/media/`
- 数据与密钥均已加入 `.gitignore`

## 首版能力

- 邮箱/密码注册登录，scrypt 密码摘要，HttpOnly 会话 Cookie。
- 邮箱验证码注册、历史账户邮箱验证、一次性链接找回密码；密码重置和禁用账户会撤销登录会话。
- 后台“注册与邮箱”管理注册开关、验证要求和新用户积分；用户详情支持填写原因禁用/恢复账户。
- 独立积分账本、任务冻结、按交付张数结算、明确失败释放积分。
- 文字生图、单参考图编辑、透明 PNG 蒙版局部重绘；参考图自动规整至最长边 4096px 内。
- 三种预设画幅、两档网站质量、每任务最多 1–4 张输出；每个模型可单独收窄支持范围。
- 后台模型目录、停用/开放、默认推荐、展示标签与说明、能力约束和按模型/任务/质量配置积分价格。
- 工作台按任务过滤模型，切换后同步参数和预计积分；提交时校验报价，模型、参数映射与单价随任务保存快照。
- 服务端任务队列、刷新后恢复查询、作品预览/缩放/下载、结果复用。
- 作品分页搜索、单项/批量删除、回收站恢复与永久清除；积分账本保留，仍被任务引用的图片受保护。
- 用户图片用量、上传次数与任务空间预留；后台配置全站每用户额度和保留时间，每小时清理到期内容。
- 图片按用户隔离，云端可在单机文件存储上持久化。
- 一次性积分兑换码；管理员可发码、查看用户/任务/订单、处理结果不明的任务。
- 微信/支付宝付款选项及 **EPay（易支付）兼容协议**订单与通知验签。默认关闭。
- 独立部署的 New API 适配器，密钥只在服务端读取。

## 连接现有 New API

从 `.env.example` 复制为 `.env`，填写配置。**不要将真实 Key 写入前端、Git 或公开截图。**

```dotenv
APP_NAME=Yidian-Image
IMAGE_PROVIDER=newapi
NEW_API_BASE_URL=https://你的中转域名/v1
NEW_API_KEY=你的网站专用受限Key
NEW_API_IMAGE_MODEL=你在NewAPI中启用的准确模型ID
STANDARD_IMAGE_CREDITS=12
HIGH_IMAGE_CREDITS=24
```

重启服务后，进入“运营管理 → 模型管理”维护图片模型。当前连接的是同步 Images 协议：

- 文生图：`POST /v1/images/generations`（JSON）
- 编辑与重绘：`POST /v1/images/edits`（multipart）
- 接受 `data[].b64_json` 或 HTTPS `data[].url`。
- 迁移的默认配置将“标准”映射为 `medium`，“精细”映射为 `high`；可在后台分别配置为 `omit`（不发送）、`auto`、`low`、`medium`、`high`、`standard`、`hd`。
- 蒙版尺寸与参考图一致；透明区域表示编辑，非透明区域表示保留。
- 配置地址可带或不带结尾 `/v1`。不支持把第三方异步 task_id 协议直接当作同步 Images 协议使用；如你的渠道返回任务 ID，需要增加对应适配器。
- `X-Request-ID` 和 `Idempotency-Key` 传递本站任务 ID，便于追踪；不假定上游因此自动具备幂等能力。

请用低额度 Key 验证文生图、参考图、蒙版、多图、实际质量参数与账单。默认价格是产品示例，**并未按你的真实模型成本测算**。

### 多模型管理

管理员入口：`/?page=admin&adminTab=models`。

**先测试，再上架：**登录管理员后，创作工作台会显示“管理员模型测试”开关。打开后可选择尚未验证或已停用的后台模型配置，无需先标记“已验证”；模型卡片上的“测试模型”也会直接打开该型号的测试工作台。普通用户及匿名访问者无法获得测试目录，也不能通过请求参数启用测试。

测试使用同一任务队列、模型参数与价格快照，按配置正常冻结/结算管理员账户积分；真实模式会产生 New API 调用费用。建议先用标准质量、1 张图验证；编辑和蒙版测试仍需上传对应素材，参数必须满足配置范围。测试任务在作品和后台中单独标记、保留审计记录。明确失败释放积分，结果不明保持冻结，规则与普通任务一致。**测试成功不会自动上架或标记已验证**，需管理员检查结果、成本和支持能力后再决定开放。

1. 添加展示名称、New API 准确模型 ID、介绍与标签，设置排序。网站模型目录与 New API 渠道分别管理，不会自动将中转站全部型号上架。
2. 选择已验证支持的任务类型、画幅、质量、数量上限。初版参数能力按模型统一配置；如同一模型的文生图与编辑尺寸限制不同，应先选择各任务均支持的共同范围。
3. 分别设置文生图、参考图编辑、局部重绘在各质量档位的每张积分价格。即使新建表单有预填示例价格，仍需按真实成本测算。
4. 配置同步 Images 适配器的 quality 参数映射、是否发送 size。关闭 size 时工作台显示“模型默认”且禁止选择画幅；实际尺寸以交付图片为准。当前预设尺寸仅覆盖 1024×1024、1536×1024、1024×1536，其他尺寸或接口需后续扩展。
   如上游返回像素与请求值不同，可在模型配置中填写“向用户展示的尺寸说明”；说明会出现在工作台，提交时保留在模型配置快照中。
5. 完成实际接口与成本验证后，勾选“已验证”与“向用户开放”，可设为默认。新建模型默认停用。

首次启用模型目录时，自动从 `NEW_API_IMAGE_MODEL` 与标准/精细积分环境变量初始化一项配置。**这些环境变量随后不再覆盖后台目录**，以后请在后台修改；已有任务和积分记录保持原值。模拟模式保留默认模型用于本地验证，真实模式下未确认联调的模型不会展示或接受新任务。首次在真实环境初始化的默认配置也会保持停用，直到管理员验证启用。

后台同时只能有一个默认启用项；停用默认项时，按排序选取其他可用项为默认；全部停用时网站显示暂无可用模型。模型配置采用版本校验，避免两个管理页面互相覆盖。编辑能力或价格后，前端要求重新确认联调。

网站前台只获得公开目录与价格，不获得密钥、网关地址或参数映射。工作台每 30 秒、窗口重新获得焦点及后台保存后更新目录。价格或版本过期时拒绝提交，用户核对新价格后再提交；不会自动改用其他模型再次生成。已排队任务保留实际上游模型 ID、展示名称、质量映射、size 发送策略与积分单价，不会因目录改价、改名或停用而变化。上游通道若被同时关闭，原任务仍可能失败，需按既有异常规则处理。

新任务提交必须携带目录 `modelId`、`modelRevision` 与 `expectedUnitPrice`，价格最终由服务端核对。重复提交同一个任务标识时优先返回原任务，即使期间型号下架或价格变化也不会重复扣费；旧任务无需这些字段即可继续查询和结算。

## 积分规则

网站积分是零售账；New API 的额度/用量是模型调用账。普通用户只在本站消费，不要求另建 New API 账户。

1. 提交任务：使用服务端价格快照冻结 `单价 × 张数`。
2. 成功交付：仅结算已保存、可交付的图片，未交付部分退回。
3. 明确拒绝/失败：全额释放冻结。
4. 超时、502/5xx、响应无法解析、重启时仍在运行：标记 `uncertain`，保留冻结，**不自动重新调用上游**。
5. 管理员核对 New API 日志与产物后，若确认没有可交付图片，可填写原因释放积分。上游费用不一定会同时退回，需要分别核对。

本站提交接口用用户与 `Idempotency-Key` 去重；同一标识的不同请求会被拒绝。重复结算、重复支付通知和重复兑换不会重复增加/减少积分。

## 管理员、用户管理与兑换码

先通过网站注册自己的账户，然后执行：

如果注册要求邮箱验证码，本机采用测试邮件模式时可执行 `npm run mail:preview` 查看最新验证码或重置链接。详细说明见 [账户与邮件](docs/ACCOUNTS.md)。真实 SMTP 尚未配置，本地测试不会向外发邮件。

```powershell
npm run admin -- promote your-email@example.com
npm run admin -- voucher 200
```

第一条提升管理员权限，刷新页面后出现“运营管理”。日常发放积分可以直接在“运营管理 → 兑换码管理”完成，无需使用命令行。第二条命令仍可生成有效期 30 天、一次性使用的 200 积分兑换码。没有预设生产管理员密码。

运营后台分为七个独立栏目：

- **概览**：统计所有账户（包含管理员、现有演示账户）、任务、待核对任务、订单及全站可用/冻结积分。总数不受列表分页限制，展示最新 5 个注册账户，并可跳转全部用户或待核对任务。
- **用户管理**：覆盖所有账户，每页 20 位，按注册时间倒序；支持邮箱、昵称、用户 ID 的包含搜索和角色筛选。展示角色、注册时间、可用积分和冻结积分，支持手动刷新、窗口重新获得焦点刷新与可见时 30 秒刷新。
- **模型管理**：配置可选模型、默认项、展示信息、支持能力、上游参数映射与独立积分价格。
- **兑换码管理**：积分码生成、历史、筛选与作废，详见下方规则。
- **任务管理**：全站任务分页查询，按状态筛选，按任务 ID、提示词、用户昵称或邮箱搜索；结果不明的任务在核对后填写原因释放积分。较早的任务同样可查询，不再只覆盖最近 100 项。
- **注册与邮箱**：管理新用户注册、邮箱验证要求与赠送积分，显示邮件配置状态。赠送积分设为 0 可关闭赠送，改动不影响已有账户。
- **存储管理**：查看用户图片用量与任务预留，配置每用户存储额度、上传限制、回收站和素材保留时间；可确认执行到期清理。详见 [作品与存储](docs/STORAGE.md)。

在用户列表、最新注册或任务所属用户处点击“查看详情”或用户昵称，可查看账户资料与统计，以及分别分页的**积分流水、成功兑换记录、任务记录**。用户列表支持正常/禁用状态筛选，详情中可填写原因禁用或恢复账户。所有时间以北京时间显示；查询不修改用户余额，也不返回密码摘要、登录令牌、完整兑换码或模型密钥。积分流水将可用余额变化和冻结变化分开显示。

管理员入口示例：`http://127.0.0.1:5173/?page=admin&adminTab=users`。刷新页面会保留当前后台栏目。所有后台接口同时检查登录状态和管理员角色；普通用户无法通过直接访问接口查询他人数据。

后台兑换码管理支持：

- 100、500、1000 积分快捷选项，也可自定义 1–100,000 积分。
- 7、30、90 天有效期，也可自定义 1–365 天；从生成时起计算截止时间。
- 可选内部备注，仅管理员可见；每次生成 1 张，整张码仅能成功兑换一次。
- 生成后展示准确截止时间（北京时间），可复制兑换码或完整发放说明。
- 完整码仅在生成成功时展示，关闭窗口或离开页面后不可恢复。服务器只存摘要与尾号；请及时复制保存。
- 历史列表按未兑换、已兑换、已过期、已作废筛选，展示创建人、备注、兑换人和时间，每页 20 条。
- 未兑换且未过期的码可填写原因作废；已兑换码不可作废，作废不会撤回已到账积分。
- 兑换码到期只限制兑换，不影响已兑换积分，当前到账积分不随兑换码到期而失效。

已有数据库自动补齐兑换码管理字段，保留旧码的摘要、原始积分、有效期和兑换记录。旧码无法恢复明文、尾号或原创建人时，列表显示“历史记录”；旧码仍按原规则兑换。创建、作废、兑换均保留审计记录。

## 微信与支付宝收款

当前实现 **EPay/易支付 MD5 通知协议适配**，不等同于微信支付 V3、支付宝 RSA2 官方直连接口，也不等同于支持所有聚合支付商。必须先按你的实际支付商文档联调。

```dotenv
PAYMENT_PROVIDER=epay
EPAY_BASE_URL=https://你的支付网关/
EPAY_MERCHANT_ID=商户ID
EPAY_MERCHANT_KEY=商户签名密钥
PUBLIC_ORIGIN=https://image.yidianhub.com
```

- 收银台：网关 `submit.php`。
- 异步通知：`https://image.yidianhub.com/api/payments/notify`，支持 GET/POST。
- 以签名、商户号、订单号、金额、付款方式、成功状态与唯一交易编号验证到账。
- 浏览器返回页只查询订单，不会凭 URL 增加积分。
- 签名正确的延迟付款仍按原订单入账；重复通知只入账一次。
- 购买选项及价格目前在 `server/config.ts` 中配置，是待测算示例。
- **退款、拒付、关单、支付商对账尚未实现**；正式收款前需要补齐。
- 如果你持有微信/支付宝官方商户，应另加对应官方支付适配器，不要填写到 EPay 配置中。

## 部署 image.yidianhub.com

采用 **GitHub Actions → GHCR 版本镜像 → 服务器 pull**。仓库：[zhuyidian/image-studio](https://github.com/zhuyidian/image-studio)，镜像：`ghcr.io/zhuyidian/image-studio`。推送 `v0.1.0` 等匹配 package.json 的版本标签后，工作流先验证测试、生产构建与实际容器运行，再发布 amd64/arm64 镜像、GitHub Release 和固定 digest 的部署包。

服务器使用 Release 中的部署包与 `compose.release.yaml`（无 build 字段），通过现有 `yidian-api-caddy-1` 的 `yidian-api_frontend` 网络服务。完整操作见 [GitHub 版本部署](docs/GITHUB_RELEASE_DEPLOYMENT.md)。New API Key 与 SMTP 授权码只在服务器环境文件配置，不写入 GitHub、镜像或部署包。

参见 [部署说明](docs/DEPLOYMENT.md)。仓库提供 Dockerfile、Compose、Caddy 配置和生产环境示例，**没有自动部署或改动 DNS/现有 New API**。

生产配置必须使用 HTTPS；默认关闭公开注册、默认无赠送积分，无演示登录。单机 SQLite MVP 每个数据库只允许一个 API/Worker 进程，服务锁会拒绝重复实例。横向扩容前应迁移 PostgreSQL、独立队列与对象存储。
